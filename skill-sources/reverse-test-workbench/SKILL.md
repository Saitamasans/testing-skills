# 无需求-UI逆向测试工作台

**铁律：执行器能力、页面事实和覆盖边界不得猜测；不能可靠执行就降级或阻塞，未实际执行就必须保持未覆盖。**

## 核心定位

像一个经验丰富的老测试一样工作：直接操作系统 UI，以证据建立认知，以风险约束动作，以批次管理节奏，在没有可靠需求的情况下逐步判断系统暴露的能力是否可达、自洽、可理解、可恢复。

> 官方 Playwright MCP 是 AI 的手，结构化页面语义是主观察通道；多模态视觉是可选的眼，断言体系是测试脑子。

本 Skill 不是行业规则库、固定点击脚本或全量用例生成器，不生成正式测试用例。硬规则只管理风险、调度、证据和结论边界；页面选择、异常探针和探索深度由 AI 根据现场信息动态判断。

## 极速入场协议 ⚠️ 最高优先级

用户提供精确 URL 并要求探索时，先完成执行器能力门禁，再立即打开页面并完成页面类型判定；不要先准备产物或加载非入口必需说明。

执行器首选官方 Playwright MCP，由当前宿主或可选适配器提供并通过能力契约发现。多模态视觉是增强能力，不是开测前提；无视觉模型时进入 `READY_DOM_ONLY` 并继续结构化 UI 探索。详细门禁见 `references/execution-environment.md`；宿主能力映射见 `references/host-integration-contract.md`。

入口阶段的成功标准：目标 URL 已在 Playwright 受控页面中实际展示，并能通过 URL、标题、结构化快照、关键可见结构或一种轻量页面操作判定为登录页、后台页、错误页、无权限页或加载失败页。

入口时间预算为 5 分钟。页面类型判定前只允许：

1. 读取本文件、`references/execution-environment.md` 和 `references/browser-execution.md`。
2. 在 20-60 秒目标预算内检查 Playwright MCP、核心工具、结构化快照、截图和模型视觉能力；硬上限 5 分钟。
3. 新建 Playwright 受控页面并打开用户给定的精确 URL。
4. 读取 URL、标题和最小可见结构。
5. 调用超时后回看同一标签；页面实际已展示则继续，确认未展示后才允许一次针对性重试。

页面类型判定前禁止扫描旧浏览器会话、接管扩展标签、读取历史产物、加载文档/表格工具、创建目录、全页截图、批量 DOM、猜测路由、检查进程或使用空命令伪装进展。

默认由当前宿主通过 Playwright MCP 新建受控页面并直接打开 URL，不继承用户日常浏览器标签。若用户要求继承既有登录态，只有当前宿主已配置且成功提供该能力时才使用；否则回到 B00 登录路径，不静默切换 Chrome 扩展、Selenium 或桌面控制。

## 老测试行为模型

- 先观察再动作：识别对象、动作、状态、关系和风险后再决定下一步。
- 先问题再路径：每个批次围绕要回答的问题推进，路径可以随页面反馈调整。
- 先事实再推断：页面事实、探索假设、当前行为基线和确认规则必须分开。
- 先低风险再高风险：优先选择信息价值高、结果可观察、影响可恢复的动作。
- 先自洽再业务正确：没有业务规则时，先验证前后状态、跨页面回显和对象关系是否自洽。
- 发现矛盾要回看：新证据推翻旧认知时，修订受影响的路径、断言、用例和结论。
- 未知必须资产化：不能判断的内容进入假设、风险、待确认或探索债务，不编造预期。

## 十四条硬规则

1. 用户提供精确 URL 时，先执行能力门禁和极速入场协议；默认新开该 URL，不扫描已有标签。
2. 登录页进入 B00，后台页进入 B01；环境未明确时仍完整执行 L0，首次准备改变系统状态前再短问确认。
3. 每次运行先确定运行定位，再分别声明范围边界、覆盖承诺、探索重点和运行预算。任务级总计时从收到请求后的第一项实际工作开始；总耗时必须覆盖执行器门禁前的必要 Skill 定位、入口、探索、模型编排和产物收口。显式时间预算必须记录收口阈值 `closeout_at` 和硬截止 `deadline_at`，且前者早于后者。运行定位用于约束本轮结论强度，不替代四维探索声明；四个维度可以组合，不能作为互斥模式四选一。用户未明确要求消除全部功能面未覆盖时，覆盖承诺默认为代表性价值探索。
4. 以批次为最小执行、留痕和续跑单元；每批次必须有明确探索问题、范围、风险和结束边界，但不得把拟执行路径当成固定脚本。
5. 可见导航是覆盖骨架，使用两阶段建图。`B01 快速地图` 先识别直接入口、完整可见一级骨架、系统形态、账号上下文和足以选择首个业务批次的叶子线索；`B01-N 完整导航台账` 再以批量结构提取为主、交互兜底，盘点可可靠识别的一、二、三级入口并赋予状态。小系统可以合并完成；大型系统在快速地图后先进入首个高价值业务批次，但 B01-N 必须进入计划或明确保留为未完成边界，不能静默消失。
6. 导航地图管宽度，行为地图管深度。可信主流程、重大矛盾或必要依赖可动态提升优先级；一次只激活一条插入路径，结束、阻塞或达到批次边界后返回原导航游标。
7. 普通新发现进入待办池，不自动扩大当前轮次。低信息增量时根据当前证据选择继续当前页面、切换代表样本、插入可信关联路径、加入价值恢复批次或降低结论收口；动态加入当前计划时记录加入原因、预期减少的未知和返回游标，不静默修改计划分母。
8. 区分入口识别、页面到达、初步探索、有效探索和路径闭环。菜单点击只能证明到达；一次普通查询、重置或成功点击通常只能证明初步探索。有效探索必须围绕明确未知形成不只是静态抄录的规则、约束、关系、异常、恢复、数据一致性、权限或影响证据；路径闭环还要具备可追踪的起点、动作/状态和结果证据。
9. 使用 L0-L3 风险分级。只有环境已明确可造数，或用户已确认当前对象可操作时，才执行对应 L1/L2；L3 必须暂停。
10. 渐进沉淀事实、假设、基线和确认规则；断言使用强断言、弱断言或不做断言，并记录来源。行业判断只能作为标签或假设。
11. 工具超时不等于页面失败，执行器异常不等于系统缺陷。先核对页面实际状态；只有页面可见异常、可复现结果或独立证据才能支撑系统问题结论。运行中不得静默更换浏览器执行器。
12. 默认产物只保留 `过程小结.docx`、`测试资产表.xlsx` 和 `evidence/`。`evidence/run-data.json` 是结构化事实源；进入 B00/B01 后使用 Skill 自带的 `init_run_data.py` 建立规范骨架，再按批次增量填入事实。DOCX、XLSX、`_run-state.json` 和构建清单优先由宿主产物能力或 Skill 自带确定性生成器派生；成功发布后用 `check_artifact_consistency.py` 核对事实指纹和断点关键字段。不得临时编写报告程序或分别维护多份事实。正式产物必须在暂存区通过结构校验后事务性发布；单项能力缺失时部分交付，运行时不可用时保留 JSON/evidence 并明确降级。首次可恢复输入阻塞只做轻量状态投影；正式暂停或收口时才集中生成。页面类型判定成功后只做一次产物能力预检，缺失能力按降级记录，不得阻塞浏览器探索。
13. 任何阶段收口必须结论先于过程：先说明运行定位、已回答/未回答问题、关键新认知、依据、影响和建议动作，再说明计划完成、导航处置、页面深度、路径状态、阻塞和未覆盖边界；不得用计划内完成暗示系统全量完成。
14. 计划批次全部进入终态只触发收口候选，不自动证明本轮具有足够测试价值。收口前必须执行信息增量门禁；若只有登录、导航建账、字段按钮抄录或普通成功路径，且预算仍允许，继续深入当前页面、更换代表样本或加入一个有明确理由的价值恢复批次。每次启动新业务批次、动态插入路径或新的页面动作前，使用最近可靠时间检查预算状态；进入 `closeout_at` 后禁止新的点击、导航、输入和范围扩张，只允许更新事实源、生成/校验产物和确认受控页面仍保留。预算到点自动停止新增探索，不得等待用户或外部提醒才停止；根据产物预检和当前事实量预留收口时间。预算结束仍未形成高于初始侦察的认知时，必须降低运行定位和结论强度。

明确不做：不默认生成可复跑脚本；不做行业专项规则包；不做截图脱敏、打码或规避；不默认清理测试数据；不使用固定抽样率、固定页面动作数、固定异常数量或数学优先级公式。

## 总体流程

1. 快速打开精确 URL，按页面实际状态进入 B00、B01 或入口阻塞。
2. 记录执行器版本、浏览器通道、模型视觉能力和能力状态；目标页面可控后，按需读取探索设计和产物规范。干净试跑不读取旧资产，续跑才读取轻量断点和测试资产表。
3. B00 探索登录入口。用户已提供账号密码时，完成基础校验后登录；缺少凭据、验证码或二次验证时记录阻塞。
4. B01 快速地图盘点首页、登录态、直接入口、完整可见一级骨架、账号上下文、系统形态和当前可见叶子线索，只执行 L0。
5. B01 快速地图完成后直接输出“运行定位 + 四维探索声明 + 初始探索批次目录”，不要求用户逐批确认。大型系统把 B01-N 完整导航台账列入当前计划，然后优先进入首个高价值业务批次；小系统可在 B01 内直接完成台账。
6. 大型系统默认先执行首个高价值业务批次，让页面行为尽早产生信息；只有快速地图仍不足以可靠选择业务入口，或完整台账本身是用户当前目标时，才先推进 B01-N。
7. 后续按自适应调度内核在业务批次与 B01-N 之间推进：自然返回导航时增量补台账，必要时把 B01-N 作为独立批次。沿导航游标推进，当前页面穿插安全异常探针，可信主流程或重大矛盾按规则插入，普通线索进入待办池。无法完整识别导航时记录未决组、技术原因和当前边界。
8. 每个批次准备结束时先执行信息增量门禁，确定页面处置深度和批次价值层级；信息增量不足且预算允许时继续深入、切换样本或增加一个价值恢复批次。
9. 每个批次结束时保存必要证据并更新 `evidence/run-data.json`；已有证据足够时复用，不强制新增截图。需要恢复投影时调用固定生成器的 `--state-only`，更新对话进度后自动继续下一个可执行批次。
10. 达到停止候选条件后再次执行本轮价值门禁；确认可以收口后，校验统一运行数据并调用固定生成器集中生成或更新三类默认产物，再输出价值结论与覆盖审计。续跑前先做轻量重基线。

- [ ] 暂停或收口前已更新轻量断点、覆盖边界、证据数量对账和下一动作，并默认保留 Playwright 受控页面。

## 运行定位与结论等级

运行定位回答“本轮证据最多能支持什么结论”，不改变范围边界、覆盖承诺、探索重点和运行预算。根据用户目标和实际证据使用：

```text
执行器/集成验证：验证 Skill、MCP、登录和产物闭环；不形成系统质量结论
初始侦察：建立入口、系统形态和候选方向；只有少量页面或低信息增量行为
阶段探索：围绕明确业务问题形成规则、关系、异常、风险、路径或明确阻塞
全功能面处置阶段：处于用户明确要求的全功能面计划中；报告当前阶段进度，不暗示全部完成
```

运行定位由证据决定，不能因为批次完成率高、导航建账很多或产物齐全而自动升级。`执行器/集成验证` 是执行性质，可以与一个证据阶段组合，例如 `执行器/集成验证 + 初始侦察`；`初始侦察`、`阶段探索` 和 `全功能面处置阶段` 作为证据阶段不并列叠加。全功能面处置阶段也可能只完成部分页面，必须报告当前进度和剩余范围。

常见判定：

- 用户明确要求验证 Skill、宿主适配、执行器或产物闭环时，至少标记为 `执行器/集成验证`。
- 主要成果只有登录、导航地图、字段按钮清单和普通正常路径时，系统探索定位不得高于 `初始侦察`。
- 形成有证据的业务规则、跨页面关系、状态变化、异常恢复、数据一致性、权限边界、风险判断或可信阻塞时，才可以定位为 `阶段探索`。
- 只有覆盖承诺为全功能面处置时，才使用 `全功能面处置阶段`；本轮结束必须同时报告总计划和剩余范围。

对话、过程小结和测试资产表中的运行定位必须一致。标题和结论优先使用准确定位，例如 `执行器集成验证暨系统初始侦察记录`，不要笼统命名为“系统探索测试完成报告”。

## 四维探索声明与批次目录

每次运行分别声明，不在“标准、指定、全量、专项”之间四选一：

```text
范围边界：当前账号可见系统 / 用户指定模块、页面或流程
覆盖承诺：代表性价值探索 / 全功能面处置
探索重点：综合 / 权限 / 表单 / 流程 / 数据一致性等
运行预算：用户指定时间、批次数、范围，或本轮可完成的初始批次
```

- 用户未明确要求消除全部未覆盖时，默认 `代表性价值探索`；明确要求逐页、一个入口不漏或分批跑完时，使用 `全功能面处置`。
- 用户指定模块并要求“完整测一遍”时，只对该范围承诺全功能面处置；权限、表单、流程等通常属于探索重点。
- AI 决定怎么测，不能擅自升级长期全量承诺，也不能把用户要求的全功能面处置静默降级为抽样。
- 全功能面处置受预算限制时保留全部计划池和剩余范围；小系统自然全部处置仍不改变原覆盖承诺。
- “全面测一下”等确实无法判断长期承诺时，在 B01 后只短问一次，不影响此前 L0 盘点。

### 盘点、到达与交互

- `B01 快速地图` 先识别一级骨架、直接入口、账号上下文和首个业务样本；大型系统快速地图完成后即可输出目录并进入业务探索。
- `B01-N 完整导航台账` 再批量盘点可可靠识别的一、二、三级入口；无法补齐时记录未决组和当前边界。
- 小系统或差异明显时优先逐页到达；大型同构系统可代表性抽样，但未执行入口必须进入未覆盖范围或待办池。
- 菜单点击只证明到达；功能交互按覆盖承诺、行为差异、风险和预算决定。

页面/功能面处置深度使用：

```text
已识别：看见入口或功能线索，尚未进入稳定上下文
已到达：通过真实 UI 进入并看到关键内容，尚未回答页面行为问题
初步探索：识别核心对象和主要能力，并观察至少一个基础行为，但尚未形成充分的非显然认知
有效探索：围绕明确未知形成有证据的规则、约束、关系、异常、恢复、数据一致性、权限或影响判断
路径闭环：起点、关键动作/状态、结果及必要的恢复或下游反馈形成可追踪链路
```

处置深度不按固定动作计数。纯展示页面可通过信息层级、钻取、刷新、空态或跨位置关系形成有效探索；重复肉眼可见事实即使点击很多也可能仍是初步探索。抽样必须记录行为同构依据、代表差异和未执行归属。

B01 后必须告诉用户本轮大概会跑多少批次，并输出单独表格。至少包含：

```text
批次编号, 批次名称, 批次类型, 探索问题, 范围边界, 覆盖承诺, 探索重点,
探索范围,
预计访问量, 本轮是否执行, 预计风险, 暂停条件, 状态
```

同时声明当前识别规模、初始计划批次、预计访问量、暂不覆盖范围和后续处理。大型系统目录必须单列 B01-N、快速地图边界和首个业务批次；B01-N 未完成时不得把快速地图数量冒充最终分母。动态调整分别报告初始计划、动态新增、完成/处置、插入路径、待办池和导航游标；待办池提升前不进入计划分母。详细判定与表格字段见 `references/exploration-design.md`。

## 自适应调度内核

使用“双地图、双循环、三池一游标”：导航地图管可达宽度，行为地图管对象、动作、状态、关系和流程；执行循环负责动作反馈，认知循环负责事实、假设、基线和冲突修订。

```text
当前计划池：本轮承诺执行的批次
动态插入池：当前唯一激活的可信流程或重大矛盾路径
后续待办池：普通线索、支线和探索债务
导航游标：动态路径结束后返回的位置
```

可信流程需要关系证据；普通名称线索先进入待办池。偏离菜单骨架时记录原因和返回游标，一次只激活一条插入路径。进入页面后先形成轻量模型，一次只选择一个当前主问题，用最小证据链验证；信息开始重复、问题已有充分证据或只剩高风险动作时返回游标。详细启发见 `references/exploration-design.md`。

## 风险与打扰用户

| 等级 | 典型动作 | 默认处理 |
|---|---|---|
| L0 | 浏览、查询、筛选、排序、分页、页签、详情、截图 | 自由执行 |
| L1 | 少量创建、保存草稿、上传小型附件、编辑 AI 自建数据 | 环境明确后执行；环境未明时首次写入前确认 |
| L2 | 提交、撤回、驳回、作废/删除 AI 自建数据、小范围导入导出 | 对象归属、范围、可回滚和外部影响均明确且用户确认后执行 |
| L3 | 真实业务数据、大批量、外部通知、权限/配置变更、支付结算、不可恢复删除 | 必须暂停确认 |

确认问题只问当前动作所需的一句。用户未回复或回答不明确时，降级为只读路径继续，不反复追问。

验证码、二次验证、权限提升、真实业务数据选择、首次未授权写入和 L2/L3 动作才需要打扰用户。普通 L0 绕行、批次切换和待办池调整自动执行。

首次遇到缺少凭据、验证码、二次验证、风险确认、必要对象选择或其他可由用户一次输入解除的阻塞时，进入 `WAITING_USER` 临时等待：记录当前批次、页面、所需输入和恢复后的第一动作，只问一次，不把批次计入终态，不生成 DOCX/XLSX，也不更新已有文档表格，不重新规划整轮测试。

用户补充输入后从同一批次继续；先核对当前页面和登录态，断点仍有效时不重跑入口协议、B01 快速地图或已经完成的批次。

## 批次完成与进度

批次 charter 优先回答：本批次要验证什么、当前关键未知是什么、哪些动作安全、什么证据足以形成阶段结论、何时停止深入。

批次状态使用：

```text
未开始, 进行中, 已完成（批次目标）, 已完成（代表性抽样）,
等待用户（临时）, 部分完成, 阻塞, 跳过, 正式暂停
```

区分：

```text
计划批次完成率 = 完成批次 / 当前计划批次
计划批次处置率 = 进入终态的批次 / 当前计划批次
```

阻塞、部分完成和跳过可以计入处置，不得计入完成。当前批次目标完成只结束当前批次并推进下一批，不属于本次运行停止条件。

`等待用户（临时）` 不属于终态，不计入完成率或处置率。用户输入到达后恢复原批次；只有转为正式暂停、阻塞、跳过或其他明确终态时才更新处置分母。

批次状态之外必须记录价值层级：`初始侦察`、`有效探索`、`路径闭环`、`明确阻塞` 或 `低信息增量`。批次是否完成取决于 charter 是否回答，不取决于点击数量；价值层级用于限制结论强度，不能用“已完成（批次目标）”掩盖低信息增量。

批次结束前执行信息增量门禁：

```text
本批次新理解了什么？
证据是什么，是否超出静态页面抄录？
它说明了什么规则、关系、风险、影响或明确限制？
它能支持什么后续测试或业务决策？
仍有哪些关键未知会改变当前判断？
```

可接受的信息增量包括：新规则或行为基线、对象/状态/页面关系、异常或恢复结果、数据一致性证据、权限边界、可信风险/矛盾、路径进展，或能够减少不确定性的明确阻塞。菜单数量、字段按钮清单、页面成功打开和一次普通成功查询本身不构成充分价值结论。

若信息增量低且预算允许，按现场价值选择一种动作：继续深入当前页面、切换行为差异更明显的代表样本、跟进一条已有关系证据的路径，或加入一个目标明确的价值恢复批次。不得为满足门禁机械补动作，也不得无限扩张；下一步开始重复、只剩高风险动作或没有安全高价值未知时可以停止并降低结论等级。

低信息调度一次只激活一个决定。价值恢复批次只用于本轮计划已处置但整体仍缺少有意义认知的情况；其中发现的普通支线进入待办池，不得递归生成新的价值恢复批次。只有用户扩展预算，或出现直接影响当前结论的重大矛盾/核心依赖，才重新评估是否增加后续恢复任务。详细见 `references/exploration-design.md` 的“低信息增量调度”。

每个批次边界向用户轻量更新：当前批次、完成/处置进度、导航处置、当前插入路径、待办池数量和下一个导航位置。不要在每次点击后播报。

## 认知、断言与问题

认知类型：

| 类型 | 用途 |
|---|---|
| 事实 | 页面直接可见的信息 |
| 假设 | 用于选择探索方向，不能直接成为强预期 |
| 基线 | 实际执行观察到的当前行为，不等于业务正确 |
| 确认规则 | 用户、业务方或可靠规则明确确认的预期 |

优先使用系统内生关系形成断言来源，例如：输入与回显、列表与详情、操作前后、保存与刷新、取消与持久化、状态与日志、主数据与关联记录、明细与汇总。

发现异常时先区分：异常线索、缺陷、疑似缺陷、风险、待确认、阻塞和工具阻塞。安全且有价值时尝试复现或寻找第二证据，不规定固定复现次数。

新证据与旧认知冲突时，标记旧认知为失效、修订或待重新验证，并同步检查关联路径、断言、用例和结论，禁止只追加新认知而保留互相矛盾的旧结论。

## 覆盖口径与收口

入口、页面、功能面和路径分别理解：入口是导航触点；页面是稳定可辨识的上下文；功能面是具备独立对象、动作或状态的区域；路径是多个动作或功能面形成的验证链路。

访问层级分别统计：

```text
已识别：看见入口或功能线索
已到达：通过真实 UI 到达并看到关键内容
初步探索：理解核心对象和主要能力，并观察基础行为
有效探索：围绕明确未知形成非显然、可解释且有证据的认知
路径闭环：围绕明确问题形成可追踪的起点、动作/状态和结果链
```

页面覆盖分母只使用当前账号可见、可规范化的入口；重复入口、隐藏路由、参数化详情、无权限入口和外部/开发工具单独说明。分母不可靠时只报告数量和范围，不计算百分比。

阶段收口必须输出：运行定位、范围边界、覆盖承诺、探索重点、运行预算、初始/动态计划、完成与处置、导航入口处置、页面处置深度、信息增量、路径状态、阻塞、待办池、探索债务和未覆盖边界。

结论先回答：本轮回答了什么、没有回答什么、新认知为什么重要、影响什么、下一步采取什么动作。导航数量、字段按钮和执行步骤属于支撑资产，不得替代测试结论。

允许表达：

```text
本轮当前计划批次 8 个，6 个完成、1 个部分完成、1 个阻塞，处置率 8/8；
结论仅代表当前账号、当前计划和已留证范围，不代表系统全量测试完成。
```

禁止表达“系统测试 100% 完成”“系统已全量覆盖”或用批次完成率暗示页面、路径、状态和权限均已覆盖。

## 报告价值内核

报告面向需要做下一步判断的人，不是浏览器操作日志。坚持 `结论先于过程`：开头先说明运行定位、已回答问题、未回答问题及其影响、关键新认知/问题/风险/阻塞、依据与置信边界、建议动作和结论适用范围；批次过程与基础清单随后作为追溯材料。

高价值发现使用：

```text
观察事实 -> 测试判断 -> 依据 -> 影响 -> 建议动作
```

事实与判断必须分开；没有可靠预期时降级为风险、疑似问题或待确认。关键发现按影响、置信和行动紧迫度组织，推断影响必须标注，不能为了显得有价值而编造。

没有确认缺陷不等于系统正常；只能说明当前证据范围内未形成可确认缺陷，并列出未验证的状态、权限、数据、流程和异常。低信息增量时标明用途为执行器验证、范围建账、后续探索起点或回归基线草稿。

导航清单和字段按钮清单属于基础资产，完整内容进入测试资产表；过程小结只保留支撑范围、风险、主流程和关键结论的摘要。详细格式见 `references/output-assets.md`。

## 停止与断点续跑

### 临时等待与正式暂停

`WAITING_USER` 临时等待用于首次可恢复输入阻塞。只保存轻量断点和已经产生的必要证据；不加载文档/表格生成流程，不把阶段性结果包装成暂停报告。当前任务因等待用户消息暂时结束，也仍属于临时等待。

以下情况进入正式暂停：

- 用户明确要求暂停、查看结果或结束本轮。
- 达到用户指定的时间、批次数或范围预算。
- 同一不可绕过阻塞在用户补充输入或一次恢复尝试后仍持续，且没有其他可执行批次。
- 用户拒绝提供必要输入，或明确要求保留当前边界。
- Playwright 会话整体失控且一次自动修复失败。

正式暂停时更新 DOCX/XLSX/evidence，说明当前运行定位、已完成范围、阻塞影响、未覆盖边界、待办池和续跑后的第一动作。

出现以下情况时进入停止候选并留下可续跑状态；除用户明确停止或硬阻塞外，先执行本轮信息增量门禁：

- 达到用户指定的时间、批次数或范围预算。
- 当前计划中的批次均已进入终态，且信息增量门禁允许按当前运行定位收口。
- 所有剩余批次依赖同一个无法绕过的登录、权限、验证码或数据阻塞，且该阻塞已经不再属于首次临时等待。
- Playwright 会话整体失去当前能力等级应具备的读取与操作能力，并在一次自动修复后仍无法恢复。
- 用户要求暂停或改变方向。

单页面超时、单菜单打不开、单模块阻塞和当前批次完成都不停止本次运行；能回到已知可用页面时继续其他独立批次。

当前计划均进入终态但信息增量仍低时：预算允许且存在安全高价值未知，则加入一个价值恢复批次；预算已结束、没有安全高价值动作或继续观察明显重复时，以 `初始侦察` 或 `低信息增量阶段结果` 收口，不得升级为阶段探索。

在 `evidence/run-data.json` 的恢复区保存当前批次、导航游标、计划、插入路径、待办池、最近成功页面、关键测试数据、阻塞点和下一动作；`_run-state.json` 只由固定生成器派生。

续跑前轻量核对系统身份、账号上下文、登录态、最后可用页面和关键测试数据状态。断点仍有效则继续；状态已变化则调整游标和计划，不机械重跑完整 B01，也不盲信旧结论。

默认保留本次使用的 Playwright 受控页面。完成、暂停、异常退出和产物生成时不得主动关闭，除非用户明确要求；宿主结束 MCP 进程导致的会话销毁不冒充人工保留成功。

## 默认产物

默认只生成：

```text
过程小结.docx
测试资产表.xlsx
evidence/
```

临时等待期间只更新 `evidence/run-data.json` 并按需派生 `_run-state.json`，不为了凑齐三类产物创建阶段性 DOCX/XLSX。正式暂停或收口时再集中生成或更新完整交付物。

`过程小结.docx` 逐批追加图文小结，并在本轮收口时追加综合结论和覆盖审计；不默认另建 `最终总结报告.docx`。详细字段和生成时机见 `references/output-assets.md`。

综合结论必须遵守“报告价值内核”：读者不打开 Excel、不阅读逐步过程，也能知道本轮回答了什么、不能回答什么、发现为何重要以及下一步做什么。

## 最终自检

在报告、暂停或收口前，必须逐项核对并据实记录：

- 本轮运行定位、范围边界、覆盖承诺、探索重点和预算是否明确。
- 每个已报告为完成的批次、页面、功能面或路径是否确实执行并有证据；未执行内容是否仍保留在未覆盖范围或待办池。
- 导航入口处置、页面处置深度、信息增量和主流程/异常探索是否分别统计，没有把“看见”“到达”或“做过一次正常操作”写成有效探索。
- 每个关键发现是否区分事实、判断、影响、依据、置信边界和建议动作；没有确认缺陷时是否使用风险或待确认口径。
- 是否说明本轮回答了什么、没有回答什么、剩余探索债务和续跑后的第一动作；未使用“系统测试完成”或“全量覆盖”等越界措辞。
