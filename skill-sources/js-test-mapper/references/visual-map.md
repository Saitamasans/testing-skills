# 可视化地图（主交付 · 定版）

没有能点开的 `evidence/map.html`，本轮不算完成。Word / Markdown / Excel / JSON 都是附录。不要产出 `run-data.json` / `cognition.json`。

**皮肤已定版。** 只填 `map.json` 再渲染。禁止改 `templates/map.html` 的配色、字体、左右栏、树形布局去「再美化一版」。参考样例：`assets/demo-map.html`（吉搭钱包）。

## 必须交付

1. `evidence/map.json`：符合 `schemas/map.schema.json`（边必须有动词 `label`）
2. `evidence/map.html`：有 Node 时 `node scripts/render-map.mjs evidence/map.json evidence/map.html`；无 Node 时复制模板并把 `__MAP_DATA_JSON__` 换成 JSON（`<` → `\u003c`）
3. 聊天：一句话定位 + 图路径 + 最多 3 条测试重点。禁止把六章底稿贴进聊天。

打开 HTML 必须能看见：模块怎么连、至少一条流程、线上有动词、点节点出「已确认 / 还没验证 / 建议先验」。默认落到节点最多的业务流。

## 定版视觉（对照 demo-map.html）

| 项 | 定版 | 禁止 |
|---|---|---|
| 布局 | 自上而下树形；子树各占一列 | 左右一条长链、回头线、交叉线 |
| 节点色 | 只按 `status`：看见了绿 / 代码里有蓝 / 推测橙 / 待验证灰。缺 status = 待验证 | 缺省成看见了、按模块名哈希上色 |
| 连线 | 弧线，从上往下分叉；**只画树边** | 正交折线、为美化改算法、画汇合/回头边 |
| 边字 | 10px、动词、可在「点」处换行 | 边字比节点还抢眼 |
| 左右栏 | 灰底白胶囊分层；右栏圆角卡片 | 深色侧栏、衬线古风 |
| HTML | 离线单文件，无 CDN | 外链字体/样式 |

推测/待验证边：`dashed: true` 且 `status` 为 `inferred` 或 `unverified`。

会交叉的非树边（回头、跨列汇合）不要放进 `edges`。误放了渲染器会丢掉，并在卡片写「未画出（汇合/回头）」；SVG 里有 `<!-- dropped from->to -->`。

## 三种图，分开画

| 图 | 内容 | 禁止 |
|---|---|---|
| 模块关系 | 模块节点 + 带动词的边 | 把菜单树当业务 |
| 每条关键业务一张小图 | 状态/步骤怎么走 | 一张图塞全部页面和接口 |
| 节点卡片 | 已确认、没验证、建议先验、证据 | 为填满而编规则 |

线必须有含义：「提交后预占库存」可以；「订单—库存」不行。

## 没证据时

画不出完整业务状态机，就只交**页面/模块关系图**，流程区写清「证据不够，不编故事」。

## 完成前自检

- 不打开 HTML 就无法理解系统 → 不合格
- 没有边标签 → 不合格（渲染器直接失败）
- 把「登录→点菜单→进列表」标成业务流程 → 不合格
- 无证据却画出完整闭环 → 不合格
- 线和节点交叉、边字盖住节点 → 不合格
- 改了定版模板才「好看」 → 不合格，回退模板
- 只交了 Word/run-data、没有 map.html → 不合格
