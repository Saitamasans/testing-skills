# JS 证据与测试认知

实际取得 JS 正文后，按 [深度分析手册](analysis-playbook.md) 做符号账本、分支链及停止判断；生成最终交付时读 [测试地图交付规范](output-specification.md)。不要仅凭关键词统计形成业务结论。

## 采集

使用宿主提供的 DOM、内嵌 script、已观察资源正文、自然请求记录。遵守 evaluate 限制，不用 fetch/XHR、脚本注入、原始 CDP、缓存抓取或另起执行器补洞。无外部正文接口就记录缺口；用户提供离线 JS/Map 可按同一合同分析。

内嵌 JS 可能含 CSRF Token/用户数据，先在读取端排除认证秘密，输出分析必需片段和位置；按本项目授权可保留必要业务原值，不默认保存整段脚本或响应。

## 分析

1. 资产清单：来源页面、声明位置、内嵌/外部、实际读取范围、是否截断、版本/内容指纹（实际计算才填）。vendor 与业务初始化分开；文件名不单独证明分类。
2. DOM 事件选择器 → handler → 条件/权限判断 → 请求声明/路由跳转 → UI 反馈，每条边附位置。动态分派无法解析则断边，标推断，不补造调用链。
3. 接口只恢复方法、路径模板、调用点、参数名；不调用接口；仅保留分析必需且已授权的业务参数原值，排除认证秘密。路由存在不等于有权限；状态判断存在不等于已知状态含义。
4. 取得 Map 正文并验证映射才认定恢复；无解析器/输入不全时，文本匹配不称 AST/完整 Map 分析。
5. Dcat/SSR 即使外部脚本共用，仍恢复菜单、标题、面包屑、表头、筛选控件、只读详情与内嵌事件。全页面 form label 可能是修改余额弹窗，不全部算筛选条件。

## 事实层级

- observed：工具实际观察的状态。
- static：已读脚本的声明，必须有脚本位置。
- inferred：有依据的推断，列 evidence_ids 与 alternatives。
- unverified：材料不足的假设/待验证。

导航关系不是函数调用关系；36 个 .on() 不证明 36 个业务功能。

## 测试认知

交付系统/模块地图、代表性功能路径、接口引用候选、权限/状态线索、风险和测试重点、未覆盖清单。建议不是测试执行结果。默认先交 `map.html`；Word 仅归档。不要写 `run-data.json` / `cognition.json`。
