# 需求澄清输出契约

本文件定义 `requirement-clarification-test` 的固定输出格式。Skill 本体只负责判断需求、整理问题和生成结构化报告；正式 Excel 由专属 renderer 生成。

## 1. 默认会话输出

默认必须同时输出四部分：

1. 开测准入总结。
2. 产品核对轻表。
3. 可直接复制给产品的问题文本。
4. Excel 下载链接。

当用户明确只要口头澄清且不要文件时，可以不生成 Excel；除此之外，凡是提到文件、Excel、xlsx、留档、发产品、复审，都必须生成文件。

### 1.1 开测准入总结

固定字段：

| 项目 | 当前结论 |
|---|---|
| 开测准入 | 可开测 / 有条件开测 / 不建议开测 / 不可开测 |
| 是否进入用例生成 | 是 / 否 |
| P0 阻断 | 数量 |
| P1 风险 | 数量 |
| P2 细节 | 数量 |
| 当前最大风险 | 一句话 |

### 1.2 产品核对轻表

只展示高价值问题，默认控制在 6 到 12 行，按 `P0 -> P1 -> P2` 排序。表头固定为：

| 优先级 | 需要确认的核心问题 |
|---|---|

不能展示影响范围、阻断状态、备注等重字段。

### 1.3 可直接复制给产品

标题固定为：

```text
可直接复制给产品
```

正文要求：

1. 可直接复制到飞书、钉钉或企业微信。
2. 使用纯文本编号。
3. 不出现问题 ID、影响范围、阻断状态等内部字段。
4. 不写 AI 分析过程。
5. 所有 P0 问题必须保留。

## 2. Excel 输出

Excel 只有两个 Sheet：

1. `产品核对问题表`
2. `需求澄清摘要`

### 2.1 Sheet 1：产品核对问题表

固定 8 列，顺序不得改变：

| 列序号 | 列名 |
|---|---|
| 1 | 问题 ID |
| 2 | 问题分类 |
| 3 | 需要产品确认的问题 |
| 4 | 影响范围 |
| 5 | 优先级 |
| 6 | 阻断状态 |
| 7 | 产品答复 |
| 8 | 备注 |

规则：

1. 不要出现 `复审状态`、`已答复状态`、`处理状态`、`测试结论`、`测试用例 ID`、`需求 ID`、`关联测试点`。
2. `产品答复` 为空表示未答复。
3. 普通问题行白底。
4. 只有 P0 行使用浅红或浅橙底色。
5. P1、P2 不要上色。
6. 表头在第 4 行。
7. 冻结前 4 行。
8. 开启自动筛选。
9. 长文本自动换行。
10. 优先级下拉：`P0`、`P1`、`P2`。
11. 阻断状态下拉：`⛔ BLOCKING`、`非阻断`。

### 2.2 Sheet 2：需求澄清摘要

四个分区：

1. 开测准入结论。
2. 当前需求理解。
3. 已明确内容。
4. 本轮不纳入。

建议字段：

- 开测准入结论：需求名称、资料来源、开测准入结论、是否可进入用例生成、是否存在 P0 阻断、当前最大风险。
- 问题统计：P0 数量、P1 数量、P2 数量、总计。
- 当前需求理解：业务目标、使用角色、入口路径、操作对象、主流程、成功结果、失败结果。
- 已明确内容：规则 ID、已明确内容、来源/依据、涉及范围、备注。
- 本轮不纳入：范围 ID、不纳入内容、原因、后续处理。

## 3. 结构化 JSON 契约

Excel 生成前，AI 必须先形成符合 `schemas/clarification-report.schema.json` 的结构化 JSON。

顶层结构：

```json
{
  "report_meta": {},
  "admission": {},
  "requirement_understanding": {},
  "confirmed_items": [],
  "excluded_items": [],
  "questions": []
}
```

### 3.1 ID 规则

1. 问题：`Q001`、`Q002`。
2. 已明确内容：`C001`、`C002`。
3. 本轮不纳入：`N001`、`N002`。
4. ID 不得重复。
5. 问题 ID 必须连续排序。

### 3.2 阻断规则

1. `priority = P0` 时，`blocking_status` 必须是 `⛔ BLOCKING`。
2. `priority = P1` 或 `P2` 时，`blocking_status` 必须是 `非阻断`。
3. 存在 P0 时，`has_p0_blocking` 必须是 `true`，`can_generate_test_cases` 必须是 `false`。
4. 不存在 P0 时，才允许把结论推进到可开测或有条件开测。

### 3.3 问题写法

1. 问题必须是产品可以直接回答的具体问题。
2. 不要只写“请确认”“规则不清”“需要补充”。
3. 不要把同一个缺口拆成很多同义问题。
4. 需要分别回答的不同规则，不要硬合并成一句。

## 4. 文件命名

默认文件名：

```text
需求澄清问题表_<需求名称>_<YYYYMMDD>.xlsx
```

若同名文件已存在，必须安全去重命名，不得静默覆盖，除非明确收到覆盖参数。

## 5. 产品答复复审

产品填写 Excel 后再次交给 Skill 时：

1. 读取 `产品答复` 列。
2. 空白仍表示未答复。
3. 有内容不代表自动关闭问题。
4. 判断答复是否完整、含糊、冲突或引出新问题。
5. 原产品答复必须原样保留。
6. 新追问使用后续连续问题 ID。
7. 只有所有 P0 真正关闭后，才允许进入后续测试用例生成 Skill。

## 6. 降级规则

1. 文件生成失败时，必须明确说明原因。
2. 不得伪造下载链接。
3. 不得声称文件已经生成。
4. 仍然要输出会话总结、轻表和可复制文本。
