# 执行规则

## 执行模型

底层能力以 Playwright 类浏览器自动化为主。
优先使用 agent-browser 类 DOM snapshot / ref 定位能力。
ref 不稳定、SPA 重渲染或弹窗切换后，降级使用 playwright-cli 类 role、aria、text 定位能力。
以 DOM、role、text、CSS selector 为主，JS eval 为辅。
截图用于证据留存和关键视觉复核，不用于 OCR 找元素，不走坐标点击。

## 定位优先级

1. DOM snapshot 中的稳定 ref：最快，但页面重渲染后必须重新 snapshot。
2. role + text / aria：较稳定，优先用于按钮、输入框、菜单、弹窗标题等可访问元素。
3. CSS selector：用于 role/text 无法稳定表达、但结构相对稳定的元素。
4. JS eval：只用于读取状态、补充输入事件或触发框架兼容事件，不得绕过业务校验或直接调用组件内部业务方法。

## 会话与状态隔离

- 默认每条用例按独立执行会话处理，避免上一个用例的残留状态污染当前结果。
- 若测试包明确要求串联执行，可在同一执行会话内保留状态。
- 若串联会引入歧义、污染数据或无法复现，应优先拆分会话或重建初始态。
- 对登录、提交、保存、发布、删除等会改变状态的动作，必须记录当前会话的状态边界。

## 停止规则

- 验证码、MFA、扫码、人机校验
- 页面状态与用例严重冲突
- 元素定位不稳定且无法可靠确认
- 目标页面需要外部人工介入才能继续
- 用例预期与当前口径明显冲突
- 继续执行可能污染数据或改变不可逆状态

## 执行器约束

本 Skill 默认不内置独立 runner，不强制下载额外执行器或浏览器安装包，优先复用现有浏览器控制能力完成执行。
不使用 Subagent-Driven 作为用例执行方式；Subagent 只可用于开发实现阶段的任务拆分，不进入验收执行链路。
