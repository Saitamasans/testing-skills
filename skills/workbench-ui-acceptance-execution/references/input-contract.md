# 输入契约

## 输入完整度分级

| 等级 | 说明 | 处理方式 |
|---|---|---|
| 完整 | 用例、环境、前置、预期、证据要求齐全 | 直接执行 |
| 可补全 | 缺少非关键项，如截图偏好或次要备注 | 按默认规则补齐后执行 |
| 可判定但不完整 | 还能跑，但部分结果需要待确认 | 执行并标记待定点 |
| 不可判定 | 缺关键预期、关键前置或目标页面信息 | 停止并反馈缺口 |
| 不可执行 | 缺少该用例必须的账号、权限、环境或外部依赖 | 标记阻塞 |

## 最低必需信息

| 字段 | 说明 |
|---|---|
| 用例 ID | 唯一标识 |
| 用例标题 | 可快速理解目标 |
| 前置条件 | 页面、数据、角色、状态 |
| 测试步骤 | 可执行的动作序列 |
| 预期结果 | 可判定的结果描述 |
| 目标环境 | 测试地址或环境标识 |
| 账号/权限 | 仅在该用例需要时提供 |
| 证据要求 | 是否必须截图、哪些步骤必须截图 |

## 账号与登录态规则

账号不是硬性前置。只有当用例目标依赖登录态、角色态、对象归属或特定账号时，账号和权限才是必需输入。

以下用例可以无账号执行：

- 登录页本身的输入校验
- 匿名可访问页面
- 注册、找回密码、引导页等不依赖登录态的页面

以下情况才算账号缺失阻塞：

- 用例明确要求已登录
- 用例明确要求特定角色
- 用例明确要求特定数据归属
- 用例目标必须在登录后页面完成
