# 输出产物与运行状态协议

创建或更新测试产物、覆盖进度、轻量断点和续跑状态时，读取本文件。

## 目录

- 产物边界
- 生成时机
- 产物能力预检
- 统一事实源与固定生成器
- 轻量运行状态
- 阶段耗时与播报
- 过程小结
- 测试资产表
- 覆盖审计
- 产物校验

## 产物边界

默认只保留三类：

```text
<系统名>_无需求UI逆向测试/
  过程小结.docx
  测试资产表.xlsx
  evidence/
    run-data.json
    _run-state.json
    _artifact-build.json
    batch-00/
    batch-01/
```

不默认生成独立的 `最终总结报告.docx`。本轮综合总结和覆盖审计追加到 `过程小结.docx`。

目标页面可控并进入 B00/B01 后才能创建产物。入口尚未成功时只在对话中报告阻塞，不创建空报告、阻塞文档或构建工程。

不把临时生成器、脚本、预览文件或渲染缓存作为用户交付物。

## 统一事实源与固定生成器

`evidence/run-data.json` 是批次、导航、页面、路径、问题、风险、测试数据、证据和认知资产的单一事实源。`过程小结.docx`、`测试资产表.xlsx` 和 `_run-state.json` 都是派生视图，不得分别手写或反向覆盖事实源。

使用 Plugin 内置固定脚本：

```text
<workspace-python> scripts/preflight_artifacts.py
<workspace-python> scripts/validate_run_data.py <run-root>/evidence/run-data.json
<workspace-python> scripts/build_artifacts.py --input <run-root>/evidence/run-data.json --output-dir <run-root>
<workspace-python> scripts/build_artifacts.py --input <run-root>/evidence/run-data.json --output-dir <run-root> --state-only
<workspace-python> scripts/record_artifact_validation.py --run-root <run-root> --status passed|failed|skipped [--reason <原因>] [--pages <页数>] [--evidence <相对证据路径>]
```

完整模式只在正式暂停或收口时生成 DOCX/XLSX；`--state-only` 只更新 `run-data.json` 和 `_run-state.json`，用于批次边界、临时等待和断点续跑。生成前必须先校验；校验或生成失败时保留已有有效产物，不输出半成品结论。

必须使用 Codex 工作区依赖解析返回的 bundled Python，不使用系统 Python，也不要求用户手工安装依赖。禁止临时创建新的报告生成器；固定生成器不得修改输入 JSON、截图或其他证据，不包含浏览器操作、探索调度或行业判断。字段契约、跨平台调用和映射规则见 `references/run-data-contract.md`。

### 集中生成生命周期

完整生成按 `预检 -> 数据校验 -> 暂存生成 -> DOCX/XLSX 结构校验 -> 事务性发布 -> 视觉校验/降级记录` 执行。结构校验通过后才能替换正式文件；任一步失败时回滚已替换项，保留原有效产物，不留下新旧混合结果。

`evidence/_artifact-build.json` 记录本轮数据指纹、生成模式、生成/跳过项、结构校验、视觉校验、耗时和临时清理。DOCX 或 XLSX 单项不可用时允许部分交付：可用项继续生成，不可用项使用 `skipped`；若旧文件仍存在，必须记录 `preserved_previous=true`，并在对话中明确它不是本轮最新产物。

同一数据指纹、请求产物和能力状态均未变化，且正式文件仍存在时，生成器返回 `unchanged`，不得重复生成和渲染。事实源、能力状态、请求产物或正式文件发生变化时才重新构建。

LibreOffice 不可用时，预检直接记录结构检查降级，完整生成器不尝试渲染。外部渲染或人工视觉检查结束后调用 `record_artifact_validation.py` 写入 `passed / failed / skipped`；只有 DOCX 已生成、页数大于 0 且至少提供一个位于运行目录内的渲染证据路径时，才允许写 `passed`。

生成器只清理当前运行根目录下、名称匹配 `.rtw-artifacts-*`、包含 Plugin 自有 marker 且超过 24 小时的暂存目录。无 marker、未过期、其他名称、evidence 截图和用户文件一律不清理。

## 产物能力预检

页面类型已经判定且准备进入 B00/B01 后，只执行一次 `artifact_preflight`，并将结果写入轻量运行状态。预检至少分别记录：

```json
{
  "artifact_preflight": {
    "checked_at": "",
    "docx_generation": "available|unavailable|unknown",
    "xlsx_generation": "available|unavailable|unknown",
    "libreoffice": "available|unavailable|unknown",
    "table_validation": "available|unavailable|unknown",
    "image_validation": "available|unavailable|unknown",
    "visual_render_unavailable": false,
    "fallback": "none|structure_check|no_artifact_generation",
    "notes": ""
  }
}
```

预检通过 `preflight_artifacts.py` 一次完成，只判断能力，不创建正式产物、不渲染空文档、不启动浏览器外的重复诊断流程。LibreOffice 不可用时直接采用结构检查，并记录 `visual_render_unavailable=true`；收口时不得先重复尝试失败渲染再降级。预检失败只限制对应产物或校验能力，预检失败不得阻塞浏览器探索；只有 Playwright 能力门禁失败才阻塞浏览器执行。同一运行只执行一次预检，续跑复用既有结果；能力状态发生变化时才重新检查并记录原因。

## 生成时机

连续探索时优先执行浏览器操作：

```text
批次执行
-> 保存必要证据
-> 更新 evidence/run-data.json
-> 按需执行 --state-only
-> 继续下一可执行批次
-> 正式暂停/预算结束/本轮收口
-> 校验 run-data.json
-> 固定生成器集中更新 DOCX/XLSX
```

以下情况集中生成或更新文档和表格：

- 用户要求暂停、查看结果或结束本轮。
- 达到时间、批次数或范围预算。
- 当前计划均进入终态，且信息增量门禁允许按当前运行定位收口。
- 所有剩余批次依赖同一不可绕过阻塞，且该阻塞已不再属于首次临时等待。

首次缺少凭据、验证码、风险确认或必要对象选择时属于 `WAITING_USER` 临时等待，不在此时生成 DOCX/XLSX，也不更新已有文档表格。只有用户明确暂停/查看结果、预算结束、阻塞在一次恢复后仍持续且没有其他可执行批次，或用户拒绝必要输入时，才转为正式暂停并生成。

不得因为加载文档工具、渲染 Word/Excel 或视觉校验而提前停止可继续的浏览器批次。

## 阶段耗时与播报

运行状态、过程小结和测试资产表使用同一套阶段计时。至少记录以下阶段的 `started_at`、`ended_at`、`duration_ms` 和 `status`：执行器门禁、入口、B00、B01 快速地图、首次业务交互、B01-N 完整导航台账、业务批次、临时等待、产物生成、产物校验和总耗时。没有发生的阶段写 `status=not_started` 和原因，不用空值掩盖；临时等待的耗时单独统计，不混入浏览器操作耗时。

任务级总计时从收到当前测试请求后的第一项实际工作开始：先记录 `timing.total.started_at`，再定位 Skill、读取入口必需说明或检查执行器。总耗时覆盖必要 Skill 定位、执行器门禁、入口、探索、模型编排、事实源维护、产物生成和最终校验；不得从 URL 打开、页面类型判定或首次业务交互后才开始计算。

根据运行预算建立明确预算截止点，并依据产物预检、当前事实量和历史生成速度预留收口时间。剩余预算不足以完成下一个主问题及可靠收口时，立即停止新增探索，保留游标和待办，进入事实源校验与固定生成器；不得等用户提醒后才停止。预留窗口按现场自适应，不把固定分钟数写成所有系统通用常量。

显式时间预算在 `run.budget_control` 中记录 `started_at`、`closeout_at`、`deadline_at`、`last_checked_at`、`status` 和 `overrun_ms`。`closeout_at` 是停止新增浏览器探索并开始收口的阈值，必须早于端到端硬截止 `deadline_at`；每次准备启动新业务批次、动态路径或新页面动作时更新 `last_checked_at`。达到阈值后不得再用点击、导航或输入追求额外覆盖。

`run-data.json` 必须在进入 B00/B01 后建立最小规范骨架，并在批次边界增量更新。不得在收口阶段首次拼装完整 `run-data.json`；若事实源尚未同步，先停止新增探索并补齐已发生事实，不得一边继续扩张一边集中回忆整个运行。

使用 Plugin 固定 `scripts/init_run_data.py` 创建骨架，不手写顶层结构、执行器键、预算对象、阶段计时和空集合。初始化器只生成跨行业通用结构，不包含页面点击、业务判断或探索结论；AI仍负责按现场证据增量更新批次、导航、页面、路径、风险和认知。

短预算默认预留至少 3 分钟或总预算 30% 中较大者用于事实源校验与固定产物；总预算不超过 3 分钟时至少保留一半。首次完整生成失败时只允许一次集中修正：先读取校验器的全部可行动错误，统一修复后重跑。仍失败则立即部分交付现有 `run-data.json`、证据和阻塞说明，不继续多轮字段试错突破硬截止。

完整生成和视觉/结构记录完成后，调用 `scripts/check_artifact_consistency.py --run-root <run-root>`。成功发布派生产物后禁止再修改 `run-data.json`；若最终事实必须变化，只允许更新后重建一次并重新检查指纹。检查未通过时不得宣称 DOCX、XLSX、断点和事实源一致。

过程播报只保留用户可采取行动或能判断进度的节点：入口完成、B01 目录形成、批次边界、风险/等待、正式暂停或收口。单次点击、截图、快照、目录检查、内部工具调用、重复读取规范和无结果动作不单独播报。详细节流规则见 `references/browser-execution.md`。

只保存续跑需要的轻量状态，不复制完整页面文本、截图内容或所有资产表字段。不得保存登录密码、验证码和敏感凭据。执行器内部错误只保留短摘要，不保存可能包含凭据或完整页面内容的原始日志。

每个批次边界、动态路径插入/退出、导航游标变化、临时等待和重要阻塞后更新。`WAITING_USER` 时只记录所需输入和恢复动作，不复制凭据。续跑成功后继续沿用同一运行状态；用户要求干净试跑时创建新的运行状态，不读取旧结论。

## 过程小结.docx

`过程小结.docx` 面向人阅读，逐批追加图文小结，不写成长篇操作流水账。

结论摘要放在批次过程之前。首次生成文档或本轮收口更新时，文档开头使用以下信息层级：

```text
运行定位与一句话结论
已回答问题
未回答问题及其影响
关键新认知/问题/风险/明确阻塞
建议动作与优先级
结论边界
批次过程与代表证据
覆盖审计
```

导航清单、字段按钮清单和截图索引属于基础资产，完整内容保留在 Excel/evidence。Word 中只引用能够解释范围、关键路径、问题、风险或行动建议的摘要和代表证据。

每条关键发现优先采用：

```text
观察事实 -> 测试判断 -> 依据 -> 影响 -> 建议动作
```

其中事实、判断和预期来源必须分开。无法形成可靠判断时降低为风险、疑似问题、待确认或明确阻塞，并说明还需要什么证据。

关键发现按影响范围、证据置信和行动紧迫度排序，不按菜单顺序或发现时间排列。影响只有证据支撑时才作为判断；推断影响必须标记为假设或待确认。建议动作尽量说明方向和优先级，能够可靠判断时再写测试、产品或开发责任方向。

每个批次章节包含：

- 批次编号、名称和探索问题。
- 运行定位、范围边界、覆盖承诺、探索重点、运行预算、账号上下文和风险边界。
- 实际进入路径和关键操作。
- 代表证据与图注；没有新增独特视觉状态时可以复用已有截图或引用结构化证据。
- 页面处置深度和批次价值层级。
- 新认知、判断依据，以及为什么不只是静态页面抄录。
- 核心事实、关系验证和行为基线。
- 主流程/矛盾/异常探针结果。
- 缺陷、疑似缺陷、风险、待确认和工具阻塞。
- 本批次说明了什么、影响什么、能支持什么后续测试或业务决策。
- 已回答问题、未回答问题和可能改变当前判断的关键未知。
- 低信息增量时的调度决定、选择依据、价值恢复目标和返回游标。
- B01 快速地图与 B01-N 完整导航台账的独立状态、数量、未决组和后续位置。
- 阶段耗时摘要、本批次耗时及明显瓶颈；临时等待与实际执行时间分开。
- 批次状态、未覆盖边界和探索债务。
- 导航游标、待办池变化和下一步。

本轮收口时在同一文档追加综合章节：

- 本轮运行定位和结论适用范围。
- 本轮回答了什么、没有回答什么。
- 主要新认知、证据、影响与行动建议。
- 系统形态、导航地图和行为地图摘要。
- 初始计划、动态新增、完成和处置概览。
- 代表功能面、页面处置深度和路径状态。
- 核心对象、观察流程和执行流程。
- 主要问题、风险、认知冲突和探索债务。
- 覆盖审计及结论边界。

导航数量、字段按钮数量、截图数量和批次完成率属于支撑信息，不得占据综合结论主体。若本轮只有低信息增量，标题和摘要必须明确使用 `执行器/Plugin 验证`、`初始侦察` 或 `低信息增量阶段结果`，不得笼统写成系统探索测试完成。

```text
优先级说明, 预计访问量, 实际到达页面/功能面, 初步探索数,
有效探索数, 路径闭环数, 导航游标, 返回游标, 动态加入原因, 未覆盖范围,
探索债务, 开始时间, 结束时间, 本批次耗时, 阶段耗时摘要,
阻塞原因, 下一步建议,
关联小结章节, 关联截图目录
```

`计划来源` 使用：初始计划、动态新增、用户指定、待办提升。

状态使用：

```text
未开始, 进行中, 已完成（批次目标）, 已完成（代表性抽样）,
等待用户（临时）, 部分完成, 阻塞, 跳过, 正式暂停
```

`价值层级` 使用：初始侦察、有效探索、路径闭环、明确阻塞、低信息增量。状态说明批次是否按 charter 进入终态；价值层级限制结论强度，两者不得互相替代。

`信息增量摘要` 说明新形成的规则、关系、异常、恢复、数据一致性、权限、风险、影响或明确阻塞。仅写“页面打开成功”“查询成功”“截图完成”不构成充分摘要。

`结论用途` 使用实际用途，例如：执行器验证、范围建账、后续探索起点、当前行为基线、自动化回归候选、业务确认、缺陷排查、权限补测、流程续跑。没有形成用途时说明低信息增量，不留空掩盖。

完成和处置分开记录。阻塞、跳过、正式暂停和部分完成不能计入完成；已进入明确终态时可以计入处置。

`等待用户（临时）` 不属于终态，不计入完成率或处置率；用户输入到达后恢复原批次。正式暂停属于本轮终态，但不计入完成。

待办候选可以记录在本 Sheet，但 `是否计入当前计划=否`，不进入计划完成率和处置率分母。提升后更新计划来源、加入原因和当前计划标记。

## 覆盖审计

任何阶段收口都必须同时在对话、过程小结和测试资产表中给出同口径审计：

```text
运行定位
范围边界
覆盖承诺
探索重点
运行预算
账号/角色上下文
执行器协议、版本、浏览器通道、模型视觉能力和能力状态
当前识别的规范化导航入口
快速地图状态与当前识别边界
B01-N 完整导航台账状态与未决组
一、二、三级导航/等价入口盘点完整性与处置
初始计划批次
动态新增批次
完成批次与完成率
已处置批次与处置率
实际到达页面/功能面
页面处置深度（已识别/已到达/初步探索/有效探索/路径闭环）
信息增量门禁结果
低信息增量原因与调度决定
价值恢复批次状态
已回答问题
未回答问题及其影响
关键新认知的影响/意义与建议动作
路径状态（推断/观察/部分执行/闭环/阻塞）
工具阻塞与系统阻塞
被动网络观察与主动接口调用数量
截图文件、截图索引和文档引用数量对账
待办池和探索债务
未覆盖范围
结论边界
```

分母不可靠时写数量、当前可见范围和限制，不计算百分比。不要把入口数、页面数、功能面数和路径数混成一个“总覆盖率”。

推荐表达：

```text
本轮当前计划 8 个批次，6 个完成、1 个部分完成、1 个阻塞，
8 个均已处置。当前账号可见的 15 个一级入口及可可靠识别的二三级入口
均已建账并具有处置状态；无法完整展开的范围已单独标明原因和边界。
本轮实际到达 24 个功能面，其中 8 个停留在初步探索、9 个达到有效探索、3 条路径形成闭环；其余为纯到达或阻塞状态。
本轮覆盖承诺为代表性价值探索；未执行功能面已进入待办池。
结论仅代表当前账号、当前计划与已留证范围，不代表系统全量测试完成。
```

综合结论优先使用：

```text
本轮定位为阶段探索，回答了 A、B 两个问题；尚未回答 C、D。
形成的新认知是……，观察事实是……，判断依据是……，它影响……，建议下一步……。
```

低信息增量时使用：

```text
本轮定位为初始侦察。已建立入口地图并完成基础路径，但尚未形成足以判断系统质量的业务规则、异常或关联证据；以下内容只能作为后续探索起点。
```

没有确认缺陷时使用：

```text
在当前账号、已到达页面、已执行路径和证据范围内未形成可确认缺陷；该结果不代表系统正常，未验证的状态、权限、数据组合、主流程和异常范围见未覆盖边界。
```

## 产物校验

生成后检查：

- 运行定位与实际证据一致，没有因 Plugin 闭环、批次完成率或产物齐全而升级为系统探索结论。
- 过程小结中的批次、状态和截图与 Excel 一致。
- 范围边界、覆盖承诺、探索重点和运行预算已分别记录，没有混成互斥模式。
- 用户要求全功能面处置时，所有规范化功能面仍在总计划池，未因本轮预算结束而消失。
- 初始计划、动态新增和待办池没有混入同一分母。
- 完成与处置没有混淆。
- 可可靠识别的一、二、三级导航或等价入口没有无状态漏项；盘点不完整处已有原因和边界。
- 快速地图和完整导航台账的数量、状态与分母没有混用；B01-N 未完成时仍保留在当前计划或未覆盖边界。
- 导航建账没有为每个菜单组重复保存整页快照或截图；批量结构结果与定点补缺证据可以对账。
- 代表性抽样均有同构依据、代表差异、未执行入口和待办归属。
- 已识别、已到达、初步探索、有效探索和路径闭环没有混淆；一次普通成功查询或重置没有自动升级为有效探索。
- 每个完成批次均有价值层级和信息增量摘要；低信息增量在预算允许时已继续探索，无法继续时已降低结论等级。
- 低信息调度只激活一个决定；价值恢复批次没有递归扩张，退出后已返回导航游标或明确说明偏离原因。
- 临时等待与正式暂停没有混淆；首次可恢复输入阻塞没有提前生成 DOCX/XLSX，恢复后没有无理由重跑已完成批次。
- 每个批次均有可追溯证据，但没有强制每批新增截图；同一状态、菜单逐项展开和重复引用没有产生重复截图文件。
- 综合结论回答了本轮回答/未回答、新认知、影响和下一步，导航与字段清单没有替代测试判断。
- 结论摘要放在批次过程之前；不阅读操作流水和 Excel 也能理解本轮价值、限制与行动方向。
- 关键发现包含事实、判断、依据、影响和建议动作；没有确认缺陷未被写成系统正常。
- 认知资产填写影响/意义、建议动作和结论用途，不能只重复页面可见文字。
- 观察流程没有被写成实际执行闭环。
- 工具阻塞没有进入系统缺陷数量。
- 执行器、浏览器、模型视觉能力和能力状态在断点、Excel 和过程小结中一致。
- 未发生静默执行器切换；若显式切换，前后证据范围和原因已记录。
- 被动网络观察未计入 UI 覆盖，主动接口调用默认为 0；非 0 时已有用户范围和风险依据。
- 失效认知及其下游资产已经更新。
- 截图可打开、编号可追溯、图注能说明证据用途；截图文件、唯一索引路径和文档引用数量已对账。
- Word/Excel 无明显截断、重叠、空白页或不可读列宽。

若文档渲染工具不可用，执行结构检查并明确记录视觉校验限制；不得因为视觉校验不可用而否定已经完成的浏览器探索。
