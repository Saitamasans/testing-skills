## 快速入口

用户提供精确 URL 时，默认新建 Playwright 受控页面并直接打开，不先扫描旧标签、进程、profile 或历史产物。

五分钟硬上限内按以下顺序执行：

```text
能力门禁
-> browser_navigate 打开精确 URL
-> 读取 URL/标题/最小结构化快照
-> 必要时轻量视口截图
-> 判定登录页、后台页、错误页、无权限页或加载失败页
```

页面类型判定前不加载探索设计、产物、Word、Excel 或 PDF 规范；不创建目录，不读取旧资产，不做全页截图、批量页面文本、进程检查、目录检查、空命令或无目标工具切换。

页面打开调用成功或超时后都要回看同一 Playwright 页面。只要目标内容已显示且能读取最小页面状态，就记录“执行器调用超时但页面已展示”并继续。确认没有形成可读取页面后才允许一次针对性重试。

入口阶段只播报真实状态变化：开始打开目标 URL、页面类型已判定、一次修复或重试仍失败。不要播报工具检索、配置文件读取、内部异常栈和无结果动作。

页面类型判定成功后，按 `references/output-assets.md` 只做一次产物预检。预检失败不得阻塞浏览器探索；LibreOffice 缺失直接采用结构检查，不在收口阶段重复尝试渲染。预检结果在同一运行内复用，除非能力状态发生变化。

禁止空命令。禁止无效目录/进程检查、重复读取相同规范、无目标工具切换和为了制造“进展”而执行的无结果动作。它们不算测试步骤、不得写入批次完成依据，也不应单独向用户播报。

只在入口完成、B01 目录形成、批次边界、风险/等待、正式暂停或收口时播报；不要为单次点击、截图、快照或目录检查单独播报。内部记录仍应保留阶段时间，用于解释执行器门禁、入口、B00、B01 快速地图、首次业务交互、B01-N、业务批次、临时等待、产物生成、产物校验和总耗时。

## 会话与登录入口

默认使用 Plugin 创建的 Playwright 管理会话，不继承用户日常 Chrome 标签或登录态。重新进入登录页是正常 B00 路径，不属于失败。

用户明确要求继承既有状态时：

1. 先判断当前 Playwright MCP 是否已经配置并验证该能力。
2. 能继承则使用；不能继承则明确说明从登录页开始。
3. 不临时安装浏览器扩展、开放调试端口、修改用户 profile，或切换其他执行器。

B00 登录探索：

- 识别标题、登录方式、账号/密码/验证码字段和辅助入口。
- 执行空提交、缺账号、缺密码等低风险基础校验。
- 用户已提供凭据时，基础观察后尝试登录；凭据不得写入产物。
- 填写密码后不要在提交前额外截图或抓取快照，立即提交后再观察结果。
- 缺少凭据、验证码、二次验证或无法判断登录失败原因时记录阻塞。

禁止暴力尝试账号、猜测密码、绕过验证码、轰炸短信/邮件验证码或操作真实账号找回流程。

## 临时等待与正式暂停

首次遇到可由用户一次输入解除的阻塞，例如缺少登录凭据、验证码、二次验证、风险确认、必要对象选择或文件路径时：

1. 完成当前可安全执行的观察并保存必要证据。
2. 在 `evidence/run-data.json` 中将运行状态设为 `WAITING_USER`，记录当前批次、URL/页面身份、所需输入和恢复后的第一动作；调用固定生成器 `--state-only` 更新轻量投影。
3. 只向用户提出当前动作所需的一句请求。
4. 保留 Playwright 页面，不关闭、不重新导航、不重新打开新会话。
5. 不得在首次可恢复输入阻塞时生成 DOCX/XLSX，也不更新已有文档表格、正式暂停报告或大规模资产表。

用户补充输入后，先轻量核对页面和登录态；上下文仍有效时从原批次继续，不重新执行入口协议、导航建图或已完成批次。页面已失效时只恢复必要上下文，不机械从零重跑。

以下才属于正式暂停：用户明确要求暂停/查看结果/结束；运行预算结束；同一阻塞在补充输入或一次恢复后仍持续且没有其他可执行批次；用户拒绝必要输入；浏览器整体失控且无法恢复。正式暂停时才集中更新 DOCX/XLSX/evidence。

普通页面加载等待、动画、长轮询或一次工具超时不进入 `WAITING_USER`，按页面状态与超时协议自行处理。

## 页面状态与超时

Playwright 工具结果与页面实际状态必须分开判断。超时后的最小核对顺序：

```text
当前 URL
-> 页面标题
-> 结构化快照中的页面特有元素或文本
-> 能使用视觉时再查看视口截图
```

不要等待所有资源、长轮询、动画或 `networkidle` 才认为页面可用。主结构已出现、关键控件可见且能进行轻量操作时，按可用页面处理。

同一路径连续两次控制失败时，返回最近已知可用页面，通过可见导航换路。当前路径可标记阻塞，其他独立批次继续执行。

只有最近已知可用页面也无法使用当前能力等级要求的读取和操作能力，且一次自动修复失败，才认定浏览器整体失控。

## 定位层级与视觉增强

默认定位顺序：

1. Playwright accessibility snapshot 中的 role、name、label、placeholder 和可见文本。
2. 表格行、邻近标签、弹窗范围、页签、列表项和稳定 DOM 关系。
3. 稳定测试属性或 CSS selector 兜底。
4. 仅在 `READY_DOM_VISUAL` 或 `READY_VISUAL_ONLY` 下，对 Canvas、地图、画布、图表、低语义控件使用截图理解和坐标操作。

视觉不是 DOM 定位失败后的万能重试。需要判断布局、图表、状态颜色、遮挡、地图点位或非 DOM 内容时，视觉可以直接成为主要观察方式；但坐标点击前必须有当前截图依据，点击后必须重新观察反馈。

`READY_DOM_ONLY` 下：

- 截图仍保存为原始证据。
- 不判断颜色、像素位置、遮挡、图表趋势、图片内容或 Canvas 状态。
- 相关功能面标为视觉未覆盖或受限，不用 DOM 文本猜视觉结论。

模块首次到达优先通过用户可见菜单、链接、卡片、页签或按钮。猜测 URL 只能用于复现、断点恢复、验证深链权限或 UI 入口异常后的替代路径，不能反向证明原入口正常。

## 两阶段导航建图

### B01 快速地图

快速地图只获取尽快开始业务探索所需的边界：

- 当前账号/角色和登录态。
- 直接入口和完整可见一级导航骨架，或非菜单系统的等价主要区域。
- 系统形态、主要业务域、明显高风险域和当前可见叶子入口。
- 当前可见导航规模、可展开节点和尚未加载的结构线索。
- 足以选择首个高价值业务批次的页面入口。

优先使用导航容器的 scoped snapshot、语义树和当前可见结构；不做全页文本搬运。快速地图完成后即可输出初始批次目录。小系统若一次结构读取即可可靠完成一至三级台账，可以直接合并 B01-N。

### B01-N 完整导航台账

执行原则是 `批量结构提取为主，交互兜底`：

1. 定位导航容器、工作区或等价入口区域，保存一个当前结构基线。
2. 使用 scoped snapshot 或 `browser_evaluate` 的只读 DOM 状态提取已加载入口，形成名称、层级、父入口、入口类型、目标/定位、展开状态和当前处置状态。
3. 对已折叠、懒加载、虚拟滚动或动态子级执行语义点击、悬浮或滚动；只读取发生变化的导航子树，并增量合并，不反复抓取和解释整页。
4. 手风琴菜单在切换下一组前先收集当前组子树，避免最后只保留一个展开组。
5. 对无法可靠解析的层级、重复入口、`#` 父组、隐藏/无权限项和外部工具进行归类，不猜测页面存在性。
6. 使用入口总量、父子关系、可展开节点与已收集子级、重复/别名和代表入口进行完整性核对。
7. 无法补齐的范围记录未决组、原因、已尝试动作和后续位置，不默认子级不存在。

`browser_evaluate` 在这里仅允许读取 DOM、ARIA、可见文本、链接目标、层级关系和展开状态；禁止主动 `fetch`、XHR、接口调用、修改页面状态或代替用户可见交互。展开和滚动使用正常 Playwright 交互工具。不得使用 `browser_run_code_unsafe` 建图。

非菜单型系统使用等价结构：看板区域与钻取入口、地图图层与对象面板、流程节点与属性区、监控资源与告警区、内容对象与处理入口。不要为了满足“菜单”概念强行查找侧边栏。

### 往返与证据控制

- 不得为每个菜单组分别保存快照、截图和完整页面解释。
- 批量结果优先落为一个规范化导航树或增量清单；只有缺口、异常结构和关键边界需要额外证据。
- 点击每个一级组可能仍是懒加载系统的必要动作，但点击之间只做当前子树提取和合并，不重新执行完整页面分析。
- B01-N 可以在自然返回导航时增量推进，也可以作为独立批次；同一时间仍只执行一个浏览器批次。
- 快速地图和完整台账分别记录数量与状态。B01-N 未完成时，快速地图数量不能作为最终导航分母。

## 访问与交互分级

B01 快速地图先建立一级骨架和业务入口线索；B01-N 再盘点当前账号可见且能可靠识别的一、二、三级菜单或等价入口。盘点只要求可靠识别入口，不要求当场深测所有页面；折叠、懒加载、权限、视觉或工具限制导致无法展开时，记录当前边界。

### 已识别

看见菜单、入口、按钮、页签、链接或功能线索，但尚未实际进入。

### 已到达

通过真实 UI 或有明确理由的替代路径进入页面/功能面，并看到能确认身份的关键内容。只有 URL 改变、空白容器或猜测路由成功不足以证明到达。

### 初步探索

识别核心对象和主要能力，并观察一个基础行为或状态反馈。查询结果变化、普通重置、分页切换、页签内容变化或基础校验通常只能证明初步探索，除非它们实际回答了非显然的规则、关系或风险问题。

展开菜单和点击子菜单属于导航交互，只证明入口可用和页面到达，不自动计入初步探索或有效探索。

### 有效探索

围绕明确未知，通过页面特有动作、关联观察或状态核对形成可解释且不只是静态抄录的规则、约束、关系、异常、恢复、数据一致性、权限或影响证据。

纯展示功能面可以不执行传统控件交互，但仍可通过信息层级、刷新、空态、错误态、钻取或跨位置关系形成有效探索；不能为了满足指标制造点击。

### 路径闭环

围绕明确探索问题，把多个动作、状态或功能面连接成可追踪链路，并保留关键观察和证据。单次无目标点击不算路径。

## 小实验执行循环

每个有意义的动作在内部按小实验思考：

```text
要验证什么？
为什么现在验证？
可能观察到什么？
结果会怎样改变当前认知？
风险和可恢复性如何？
```

不要求把内部问题全部输出。执行循环保持为：

```text
结构化观察 -> 必要时视觉观察 -> 提问 -> 判断风险/价值
-> 动作 -> 观察反馈 -> 截图/记录 -> 更新认知与调度
```

页面反馈优先于预先拟定步骤。动作不能产生新信息、开始重复或只剩高风险选择时，结束当前深入并返回导航游标或待办池。

## 批次执行与绕行

批次开始时简短声明目标问题、范围、拟操作、风险、数据策略和暂停条件；声明不是确认请求，普通 L0 直接执行。

批次中记录：

- 页面/功能面身份和真实进入路径。
- 核心对象、动作、状态、关系和反馈。
- 实际输入的数据和页面回显。
- 断言来源、问题分类和证据编号。
- 新流程候选、重大矛盾、待办池线索和探索债务。
- DOM/视觉能力限制及其影响范围。

单页面、单路径或单模块失败时：

1. 核对页面实际状态。
2. 尝试当前页面内的轻量替代操作。
3. 返回最近可用页面或导航游标。
4. 记录阻塞并继续其他独立批次。

不要因为一条列表路径失败推断所有列表、整个模块或整轮探索均不可用。普通 L0 绕行不询问用户。

批次结束只保存必要证据并更新 `evidence/run-data.json`。需要续跑投影时调用固定生成器 `--state-only`，不独立维护 `_run-state.json`。`WAITING_USER` 临时等待不生成 Word/Excel；正式暂停或收口时才调用完整生成模式，避免产物渲染打断后续浏览器操作。禁止在运行目录临时创建报告生成器。

## UI、网络与主动接口

- 页面正常交互触发的网络请求仍属于 UI 路径的一部分。
- Playwright 的网络请求列表和控制台消息只作为被动证据，单独统计，不计入 UI 到达、功能交互或路径覆盖。
- 默认禁止在页面上下文通过 `browser_evaluate`、`browser_run_code_unsafe`、`fetch`、XHR、GraphQL 客户端或直接调用内部接口进行主动探测。
- `browser_run_code_unsafe` 不用于绕过 UI 或风险门禁；`browser_evaluate` 仅做必要的只读状态补充。
- 禁止用主动接口结果替代 UI 操作，也禁止用接口成功反向证明 UI 正常。
- 用户明确要求接口测试时，应切换到独立测试范围、风险边界和对应 Skill。

## 执行器问题与系统问题

以下默认属于执行器或工具阻塞，不能直接写成系统缺陷：

- Playwright 调用超时但页面状态未知。
- 元素引用失效、定位不稳定或截图接口失败。
- MCP 会话丢失、页面引用失效或浏览器组件缺失。
- 只有工具报错，页面没有对应可见异常。
- 当前模型没有视觉能力，导致 Canvas/图表无法判断。

系统问题至少需要一种可靠依据：

- 页面可见错误、异常提示或不一致状态。
- 同一 UI 路径在安全条件下可复现。
- 前后状态、列表详情、日志记录等独立证据相互印证。
- 明确的通用质量关系被破坏，例如成功提示后结果未保存。

工具异常同时伴随页面可见问题时，分别记录工具影响和系统表现，不把两者混为一个结论。

异常首次出现时先记为线索。安全且有价值时复现或寻找第二证据；预期不可靠时降级为疑似缺陷、风险或待确认。

## 证据分级与最小留证

证据根据证明用途分级，不根据工具类型堆数量：

```text
结构/范围证据：页面身份、导航树、功能面结构、账号可见范围
行为/路径证据：动作前后、状态变化、恢复、关联页面或路径节点
问题/矛盾证据：异常现场、复现/第二证据、跨页面不一致
阻塞/能力边界证据：权限、验证码、缺少数据、工具或视觉能力限制
视觉证据：布局、图表、Canvas、地图、颜色、遮挡或非 DOM 状态
```

证据可以是截图、结构化快照、规范化导航树、页面状态记录、被动网络/控制台观察或轻量断点。截图优先承担人类可读和视觉状态证明，不要求所有事实都截图。

保留新截图前判断：

- 是否证明了尚未留存的页面身份、独特状态或关键变化。
- 是否直接支撑问题、风险、阻塞、视觉结论或路径关键节点。
- 现有截图加结构化观察是否已经足够证明当前结论。
- 新截图是否只是重复同一页面同一状态、每次点击或每个菜单展开。

同一页面同一状态不重复截图。一份证据可以关联路径、问题、认知和报告多个位置；复用时在索引中说明证明内容，不复制文件。

每个批次必须有可追溯证据，但不要求每个批次生成新的截图。导航建账批次可以使用导航概览、规范化结构树和缺口证据；普通恢复到已留存基线时可以复用基线截图，并记录恢复后的结构化状态。

原始截图放在 `evidence/batch-xx/`。不打码、不裁剪、不脱敏、不规避页面业务字段；登录凭据不进入截图。

优先截图：

- 首次进入的代表功能面。
- 关键交互前后发生的可见变化。
- 主流程的重要状态节点。
- 缺陷、疑似缺陷、风险和阻塞。
- 能代表同构功能面的结构。
- 视觉未覆盖但需要人工复核的页面。

同一页面同一状态不重复截图。问题截图可同时承担路径或状态证据。多步骤流程只保留能解释关键变化的节点，不为每次点击截图。

菜单建账不为每个一级组逐项留图。通常保留导航概览、规范化导航树和无法批量识别的缺口证据；只有菜单结构本身存在异常、权限差异或视觉问题时才增加对应截图。

命名建议：

```text
B02_S001_用户列表代表页面.png
B02_P001_查询后结果变化.png
B02_I001_保存提示与结果不一致.png
B02_BLK001_权限阻塞.png
B02_VU001_视觉能力未覆盖图表.png
```

编号含义：`S` 结构/到达，`P` 路径/状态，`I` 问题，`BLK` 阻塞，`VU` 视觉未覆盖。

每个批次和最终收口都做证据对账：保留的截图文件数、截图索引唯一文件数、文档引用截图数应可解释。所有保留截图原则上进入索引；未进入过程小结的截图标记为“仅资产索引引用”，不得静默成为孤儿文件。

截图只是状态证据，不能单独证明因果。关键结论还要关联实际路径、动作和观察结果。`READY_DOM_ONLY` 下截图不能成为 AI 视觉判断来源。

## 页面生命周期

默认保留本次 Playwright 会话中的目标页面。批次完成、暂停、异常退出、达到预算和生成产物时均不得主动关闭目标页面。

只有用户明确要求关闭，或关闭页面本身就是测试动作时，才允许关闭。若宿主在任务结束时自动销毁 MCP 进程和浏览器会话，应如实说明会话生命周期限制，不能声称页面仍保留。
