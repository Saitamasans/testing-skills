# 预检、播报与耗时验收场景

## 目标

验证入口成功后只做一次产物能力预检，预检失败采用明确降级而不阻塞浏览器探索；同时减少无效播报和工具往返，并让运行状态能够解释时间到底花在哪里。

## 场景 A：一次性产物能力预检

现状：页面类型已经判定为登录页或后台页，运行即将进入 B00/B01。

期望：只进行一次 `artifact_preflight`，分别记录 DOCX 生成、XLSX 生成、LibreOffice、表格校验和图片/截图校验能力；后续批次复用预检结果，不重复读取环境规范或重复探测同一能力。

## 场景 B：LibreOffice 缺失

现状：DOCX/XLSX 可以生成，但 LibreOffice 不可用。

期望：能力状态记录为可生成但 `visual_render_unavailable`，直接采用结构检查或其他已声明降级；收口时不再先尝试一次失败渲染再重试，不把该工具缺失误报为浏览器探索阻塞。

## 场景 C：产物预检失败

现状：某一项文档、表格、图片或渲染能力不可用。

期望：预检失败只限制对应产物或校验能力，不阻塞 Playwright 浏览器探索；对话和最终资产明确记录降级范围。只有官方 Playwright MCP 能力门禁失败才阻塞浏览器执行。

## 场景 D：无效往返

现状：AI 在入口前后出现空命令、无效目录/进程检查、重复读取相同规范、无目标工具切换或重复确认。

期望：执行协议明确禁止这些动作；它们不应被当作进展，也不应成为正式阶段或批次。

## 场景 E：用户可见播报节流

现状：探索持续进行，页面内有多个点击、快照、筛选和证据动作。

期望：只在入口完成、B01 目录形成、批次边界、风险/等待、正式暂停或收口时播报；单次点击、截图、快照、目录检查和内部工具调用不单独播报。

## 场景 F：耗时可解释

现状：本轮从执行器门禁到产物收口经历多个阶段。

期望：`_run-state.json`、过程小结和测试资产表记录一致的阶段时间：执行器门禁、入口、B00、B01 快速地图、首次业务交互、B01-N 完整导航台账、业务批次、临时等待、产物生成、产物校验和总耗时。未发生的阶段使用 `未发生`，不能用空值掩盖。

## 通用验收

- 任务级总计时从收到当前请求后的第一项实际工作开始，覆盖必要 Skill 定位、门禁、入口、探索、模型编排和产物收口。
- 显式时间预算必须形成预算截止点并自适应预留收口时间；到点自动停止新增探索，不依赖用户提醒。
- 进入 B00/B01 后建立最小 `run-data.json`，批次边界增量更新；收口时不得首次回忆并拼装完整事实源。

- 预检发生在页面类型判定之后、正式产物生成之前，并且同一运行只执行一次。
- 产物预检不替代 Playwright 能力门禁，也不改变运行定位。
- 浏览器探索优先继续；文档/表格/渲染能力问题按能力边界记录。
- 阶段耗时使用统一时间基准和 ISO 时间戳，能计算总耗时并解释等待、浏览器操作和产物工程占比。
- 预检、播报和计时字段只在运行状态和产物协议中定义一次，避免多个文件产生冲突口径。
