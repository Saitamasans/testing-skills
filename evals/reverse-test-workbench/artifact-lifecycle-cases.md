# 产物生成生命周期验收场景

## 目标

验证正式产物只在暂停或收口时集中生成，生成前后具备能力降级、结构校验、事务性发布、审计清单和受控临时目录清理。

## 场景 A：一次性能力预检

期望：`preflight_artifacts.py` 一次返回 DOCX、XLSX、LibreOffice、表格校验和图片校验能力；LibreOffice 缺失时直接声明结构检查，不执行失败渲染。

## 场景 B：单项生成能力缺失

现状：DOCX 或 XLSX 能力不可用。

期望：可用产物、`run-data.json`、`_run-state.json` 和构建清单继续生成；不可用项标记为 skipped，已有旧文件不删除但明确标记为 preserved_previous，不把它声称为本轮最新产物。

## 场景 C：结构校验失败

现状：暂存 DOCX/XLSX 缺少必要章节、Sheet 或固定表头。

期望：发布前失败，不替换正式目录中的已有有效文件。

## 场景 D：发布中途失败

现状：多个暂存文件已经通过校验，但替换第二个目标时发生异常。

期望：事务性发布恢复所有旧文件，不留下新旧混合版本或孤立备份。

## 场景 E：构建审计清单

期望：每次完整或轻量生成都写入 `evidence/_artifact-build.json`，记录运行编号、模式、生成/跳过/保留项、结构校验、视觉降级、耗时和受控清理结果。

渲染或人工视觉检查完成后，使用固定记录器写入 `passed / failed / skipped`，不重新生成 DOCX/XLSX，也不直接手改清单。

## 场景 F：崩溃遗留清理

现状：输出目录存在过期 `.rtw-artifacts-*` 暂存目录。

期望：只删除位于当前运行根目录、名称匹配、含 Plugin 自有 marker 且超过时限的目录；无 marker、未过期或其他名称的目录一律保留。

## 场景 G：临时等待

期望：`--state-only` 不生成或校验 DOCX/XLSX，只事务性更新事实源、轻量状态和构建清单。

## 通用验收

- 完整生成只在正式暂停、预算结束或收口发生一次；后续内容变化时才重新生成。
- 结构校验通过后才发布正式文件。
- LibreOffice 不可用时不尝试渲染，不把视觉未校验写成视觉通过。
- 部分交付必须在对话和构建清单中说明缺失项及旧文件状态。
- 临时清理不得触碰 evidence 截图、用户文件、无 marker 目录或其他运行目录。
