# 统一运行数据与固定生成器验收场景

## 目标

验证浏览器探索只维护一个结构化事实源，DOCX、XLSX 和轻量续跑状态由 Plugin 固定生成器派生，避免每次临时开发报告代码和多份资产口径漂移。

## 场景 A：单一事实源

现状：探索已形成批次、导航、页面、路径、问题、风险、证据和认知数据。

期望：统一写入 `evidence/run-data.json`；`过程小结.docx`、`测试资产表.xlsx` 和 `_run-state.json` 不再独立维护业务事实。

## 场景 B：固定生成

现状：运行达到正式暂停或收口。

期望：调用 Plugin 内置 `build_artifacts.py`，从同一 JSON 一次生成 DOCX、10 Sheet XLSX 和轻量状态投影；禁止临时创建新的报告生成器。

## 场景 C：结构校验

现状：JSON 缺少运行标识、结论边界、批次数组或使用不支持的 schema 版本。

期望：生成前失败并指出字段位置，不输出半成品；数组为空可以接受，但不能缺少契约要求的顶层结构。

## 场景 D：敏感信息

现状：运行数据中出现 password、token、cookie、authorization、otp 等敏感键。

期望：校验器拒绝生成，不让凭据进入 DOCX、XLSX 或状态文件。

## 场景 E：跨平台路径

现状：Plugin 在 Windows 或 macOS 的 Codex 运行时执行。

期望：脚本只使用 Python `pathlib` 和参数路径，不包含盘符、反斜杠拼接、系统 Python 假设或用户目录硬编码；由 Codex 工作区依赖解析提供 Python 解释器。

## 场景 F：空资产类别

现状：本轮没有确认问题、测试数据或执行闭环。

期望：XLSX 仍保留固定 10 个 Sheet 和表头，DOCX 如实写“当前没有对应记录”，不得编造内容或省略 Sheet。

## 场景 G：临时等待轻量投影

现状：运行进入 `WAITING_USER`，只需要保存事实源和恢复上下文。

期望：调用 `build_artifacts.py --state-only`，只更新 `evidence/run-data.json` 和 `_run-state.json`，不创建或更新 DOCX/XLSX。

## 场景 H：价值型报告

现状：JSON 同时包含结论和大量导航字段。

期望：DOCX 先展示运行定位、回答/未回答问题、关键发现、影响、建议和边界；导航与字段清单进入 Excel，不占据报告主体。

## 通用验收

- `schema_version` 明确且可校验。
- 所有集合使用稳定 ASCII 键，展示层再映射为中文列名。
- 证据路径相对于运行目录，生成器不复制或修改截图。
- 生成器可以重复运行并覆盖同名派生文件，不修改输入 JSON。
- 生成器失败时不删除已有有效产物。
- 固定生成器不包含浏览器点击、行业规则或探索调度逻辑。
